# Synthetic fixture — lessons

All lessons below describe invented rounds and simulated no-link sources, not findings about real collaborative software. Recheck applicability before using any pattern in real work.

| ID | Pattern and scope | Simulated evidence and quality | Check before proposing | What would revise the lesson |
| --- | --- | --- | --- | --- |
| L1 | Changing the domain need not change the mechanism. | R1 72/78/88/82 with SIM-S1; R5 70/82/86/81 with SIM-S5, in Novelty/Impressiveness/Feasibility/Evidence quality order. Fictional overlap only. | State the residual guarantee after the closest baseline and a distinguishing trace. | An actual absent guarantee with a different mechanism, not a new title. |
| L2 | A partition claim needs an information premise. | R3 unscored builder discard; SIM-S3 is a simulated local two-history argument, not external authority. | Ask what locally observed fact distinguishes revocation from no revocation. | An available explicit premise that distinguishes those histories, without silently changing constraints. |
| L3 | Explanation polish is not yet a contribution. | R6 90/87/78/77 with SIM-S6 in the same section order; R9 unscored duplicate of SIM-S8. Fictional interaction/resolver designs, no user study. | Specify the user's decision, strong alternative, and changed guarantee. | A different mechanism with a falsifiable task benefit; hypothetical until checked. |
| L4 | Two high section scores cannot compensate for another failure. | R7 Novelty 96, Impressiveness 95, Feasibility 62, Evidence quality 85 against 94/94/80/80. Simulated potential judgments, not measurements. | Require every configured section and all hard constraints; challenge dependency-summary assumptions. | New evidence justifying a new review; retain historical R7 scores and failed Feasibility. |

What worked in the synthetic narrative: splitting convergence, authority, repair cost, and user agency kept the frontier diverse. This is a teaching choice, not evidence that a real process improved research. See [calibration](calibration.md) and [audit caveats](validator-audits.md).
