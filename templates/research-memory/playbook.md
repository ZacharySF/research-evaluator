## Before each bounded batch

Read this file, angle-map.md, lessons.md, calibration.md, validator-audits.md, `rubric.json`, and the latest verbatim `evaluation-roundN.json` receipts. Use full packaged role instructions in fresh generic contexts, not similarly named global Determine-specific agents. Check whether the user authorized an improvement loop: evaluate-once still stops after its one JSON review. Memory is evidence to recheck, not authority.

1. For a new candidate, build the idea pool before choosing (SKILL.md "Build each new candidate from a large, triaged idea pool"):
   - verified audience gaps, then hundreds of lens ideas;
   - a backtested per-idea prior-art triage, with survivors only;
   - one carried step combined from survivors;
   - a two-vocabulary red-team, then a deep kill-search on at most two finalists.

   Each lens and family must be genuinely distinct, not a renamed version of a closed idea. State the information gained and a decisive kill question.
2. Check closest primary sources in both the cooperative and the adversarial home field, plus the audience's own work on the problem: their limitations, later work and applicability, before polishing. Record observed source claims separately from inference and proposed results. Potential review does not require a prototype merely to qualify; measured mode requires the actual evidence specified by the rubric.
3. Preserve candidate version, fresh provenance, native custom review JSON, prediction made before review, reviewer mode, and next action with its acceptance check. BLOCKED reviews retain all configured sections with null scores and `passed: false`; discard is an unscored builder outcome, not an evaluator verdict.
4. After the batch, update the map and atlas together, extract evidence-backed lessons, compare predictions (builder, triage, screen) with independent scores when available, and select the next deliberately diverse batch. After a failed judged round, include at least one pipeline improvement (more sources, new lenses, triage templates or standing kill rows for the missed field, or a packaging ledger row) with its check. Do not erase failed directions or count repeated wording as progress.
