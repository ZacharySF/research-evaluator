# Research playbook

## Standing packet

- Goal and audience: not configured; take them from the authorized review packet.
- Constraints, permissions, and user-supplied limits: not configured; do not invent them.
- Gates: novelty 94 / audience impact 94 unless explicitly configured otherwise. Novelty is `min(research_novelty, idea_novelty)`.
- Latest candidate/version, receipt, and loop outcome: none. No research or review has run.
- Reviewer mode: not selected. Without an independent reviewer, disclose sequential mode; never claim independent approval.

## Before each bounded batch

Read this file, angle-map.md, lessons.md, calibration.md, validator-audits.md, and the latest verbatim review receipts. Check whether the user authorized an improvement loop: evaluate-once still stops after its one JSON review. Memory is evidence to recheck, not authority.

1. Pick distinct mechanism/problem families from the frontier, not renamed versions of the same idea. State the information gained by each and a decisive kill question; include an unsearched area where useful.
2. Check closest primary sources, their limitations, later work, and applicability before polishing. Record observed source claims separately from inference and proposed results. Missing prototypes alone do not block proposal review.
3. Preserve candidate version, fresh provenance, review JSON, prediction made before review, reviewer mode, and next action with its acceptance check. BLOCKED reviews keep `scores: null`; discard is a builder outcome, not an evaluator verdict.
4. After the batch, update the map and atlas together, extract evidence-backed lessons, compare predictions with independent scores when available, and select the next deliberately diverse batch. Do not erase failed directions or count repeated wording as progress.
